CodeUp accessibility support

What CodeUp is

CodeUp is a beginner Python learning IDE designed to work with existing assistive technology.

It does not replace NVDA, JAWS, Windows Narrator, VoiceOver, Orca, Braille displays, or VS Code.

Supported assistive technology workflow

CodeUp is designed to work with NVDA, JAWS, and Windows Narrator on Windows; VoiceOver on macOS; and Orca on Linux. VS Code screen reader mode is a useful next step for students moving to a professional editor.

Testing has been manual where these tools were available. CodeUp needs more testing with daily screen reader users.

Keyboard-only use

  • Use Tab and Shift+Tab to focus the command input and other controls.
  • Press Control+Enter in the editor to run code.
  • Press Control+Shift+P to open command help.
  • Use the editor arrow keys to move through code.
  • Type enable screen reader mode to turn on the mode.
  • Type export for VS Code to prepare a project handoff.

Screen reader notes

Normal command results are sent to a polite live status region. Errors use an assertive alert region. Browser text-to-speech can run alongside a screen reader or be turned off in Accessibility settings to avoid duplicate speech.

Speech support

Browser speech recognition depends on browser support. Chrome and Edge usually provide better Web Speech API support. Typed commands are always available as a fallback.

Known browser limits

  • Microphone permission is controlled by the browser.
  • Audible text-to-speech cannot be fully tested by automated unit tests.
  • Screen reader behavior varies by operating system, browser, and screen reader.

Non-AI tools

Deterministic tools include preflight, indentation checks, code map, read current block, go to definition, find references, safe rename, trace navigation, breakpoint management, edit commands, sandbox checks, expected output checks, project checks, CSV preview, and safe import guidance.

What was tested

Project checks include the pytest suite, frontend tests, Ruff, Python compilation, the live local IDE, deployed IDE loading, deterministic no-AI coverage, and ARIA live-region tests.

What still needs real user testing

Daily NVDA, JAWS, VoiceOver, and Orca use; Braille display workflows; and classroom use with visually impaired beginners still need direct testing with users.
