CODEUP

Quick How-To Guide

For learners and instructors

CodeUp is a browser-based Python learning environment for beginners. You can write and run Python, inspect output, ask questions about code, understand errors, use guided learning tools, and work inside an instructor-managed classroom.

Open CodeUp: https://code-up-fmqr.onrender.com/ide

Start in five minutes

  1. Open CodeUp and wait for the workspace to finish loading.
  2. Move to the Code editor and type a short Python program. 
    name = "Learner"
print("Hello", name)
  3. Press Ctrl+Enter or use Run.
  4. Check Program output. Change the name, run again, and confirm the output changes.
  5. Use the command box to ask something such as "explain this code" or "give me a code map".
  6. If your instructor has given you a class code, open Classroom and join with your name and code.

Good to know: Voice control is optional. Every core learner task can be completed with the keyboard and normal on-screen controls.

Write and run Python

  • Type Python directly into the editor.
  • Use normal Python indentation. By default, Tab moves to the next control and Shift+Tab moves to the previous control, so keyboard users can always leave the code editor. Use Ctrl+] to indent a line and Ctrl+[ to outdent it. If you prefer Tab to indent code, turn off "Tab Leaves Editor" in CodeUp's display and accessibility settings.
  • Press Ctrl+Enter or Run.
  • Read Program output after each run.
  • If the program fails, leave the error visible and ask CodeUp to explain it before changing everything at once.

2. Program input, output, and errors

Using input()

When a running Python program reaches input(), CodeUp can ask for the value while the program is waiting.

name = input("What is your name? ")
age = input("How old are you? ")
print(name, age)
  • When the input prompt appears, type the answer into the input field.
  • Press Enter in the field, or activate Submit with Enter or Space.
  • Use Escape or the Cancel button to cancel the active prompt.
  • For several input() calls, answer each prompt in order. CodeUp continues to the next prompt automatically.
  • Answers such as run, stop, yes, no, hello, 16, Alex, or one are treated as program input while the program is waiting for input.

Alternative input commands: You can also use short commands such as "read input prompt", "use Alexis", "use 16", "read input values", "clear input values", and "cancel input".

When something breaks

A simple debugging loop works well: run the code, inspect the actual error, find where it happened, understand the cause, make one change, then run again.

Review changes before keeping them

For meaningful edits, use the change-review workflow instead of accepting changes blindly:

  • what changed
  • read before and after
  • explain this change
  • is this risky
  • apply this change
  • undo last change
  • compare before and after

5. Classroom guide for learners

Join a class

  1. Open Classroom in the main IDE.
  2. Enter the class code provided by your instructor.
  3. Enter your learner name and select Join.
  4. You can also type a command such as "Join ABC123".

Assignments

  • Open a published assignment from the classroom area.
  • Read the title and instructions before editing.
  • Write and run your code in the normal IDE.
  • Use only the kinds of assistance allowed for that assignment.
  • Submit when the code represents your intended answer.
  • Use Back to IDE or Back to CodeUp to return to the normal workspace.

6. Instructor quickstart

Instructor sign-in: https://code-up-fmqr.onrender.com/classroom/instructor/login

Set up a class

  1. Create an instructor account and sign in.
  2. Create a cohort with a clear name, for example "Python Beginners - Cohort A".
  3. Share the cohort join code with the intended learners.
  4. Create an assignment with a title, instructions, optional starter code, dates if needed, expected concepts, and assistance policy.
  5. Review the assignment, then publish it.
  6. Keep the cohort dashboard open during class to monitor learners, submissions, and help requests.

What the instructor dashboard is for

AreaUse
LearnersSee enrolled learners, recent activity, status, and progress.
AssignmentsCreate, publish, duplicate, schedule, and review work.
Help queueSee waiting learners, mark a request as helping, and resolve it.
SubmissionsInspect saved/submitted code and run information.
Assistance policyChoose what kinds of CodeUp help are allowed for an assignment.
ReportsReview cohort progress and export classroom data when needed.

Optional instructor tools

  • Create custom lessons for a specific concept.
  • Create guided projects with deterministic checkpoints.
  • Archive completed cohorts and reactivate them later if needed.
  • Use learner detail pages when you need a closer look at progress or submissions.

Before the first session

  • Test instructor sign-in and create a sample cohort.
  • Join once from a learner browser using the class code.
  • Publish and open one sample assignment.
  • Test a help request and one submission.
  • Confirm Run, output, input(), and the command box work on the learner devices you will use.

7. Troubleshooting and useful links

ProblemWhat to try
Voice does not respondType the same command instead. If you want voice, check browser microphone permission and make sure voice listening is active.
A command is misunderstoodUse a shorter phrase or type the command. The Help / all commands surfaces show supported actions.
Program is waiting for inputAnswer the visible input prompt, or use a short value command such as "use Alexis" or "use 16".
Program output is very longAsk "how many lines of output", "first line of output", or "last line of output", then use "read output" when needed.
Assignment is not visibleAsk the instructor to confirm that it is published and currently available, then refresh the classroom view.
Code produces an errorRun once, keep the error visible, and try "explain error" or "where did it crash" before requesting a full fix.
A project/file cannot be foundUse "read project files" or "project map" to confirm the active project and file names.
