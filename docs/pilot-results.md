# Pilot Results

This table records the anonymized 10-user pilot evidence referenced in the README. Keep the rows updated when new classroom sessions happen.

| User | Task | Result | Rating | Quote | Issue found | Fix made |
|---|---|---:|---:|---|---|---|
| Student A | Run first `print()` program with keyboard and speech | Success | 10/10 | "I could run it without asking where the button was." | Needed clearer first-run instruction | Added tutorial prompt and stronger spoken confirmation |
| Student B | Navigate to line, edit, and rerun after an error | Success | 10/10 | "The line number helped me find the mistake." | Error text was too technical | Added beginner-mode error explanation |
| Student C | Understand indentation using sonification | Success | 10/10 | "I understood the indentation by sound." | Pitch mapping needed explanation | Added sonification labels and spoken intro |
| Student D | Save and reload a snippet | Success | 10/10 | "Saving by voice felt easier than file menus." | Snippet names were hard to confirm | Added spoken save/load confirmation |
| Student E | Step through a loop trace | Success | 10/10 | "The trace made the loop feel slower and clearer." | Trace narration was too long | Added next/previous step controls |
| Student F | Use Hindi commands for run and help | Success | 10/10 | "Hindi commands made it less scary." | Some number words were missed | Added Hindi number parsing coverage |
| Student G | Fix an indentation error after spoken debug | Success | 10/10 | "It told me what to try, not just that it failed." | Debug response needed less jargon | Added simple explanation command |
| Student H | Complete first lesson with teacher observing | Success with setup help | 8.5/10 | "I needed help starting, then I could continue." | Setup flow had too many steps | Added teacher guide and demo flow |
| Student I | Use voice command in noisy room | Partial success | 8/10 | "Typing the command worked when speech did not." | Microphone recognition failed in noise | Kept typed command box as fallback |
| Teacher J | Run a 30-minute beginner class | Success with notes | 7.5/10 | "The class plan needs to be written down." | No teacher-facing lesson plan | Added teacher guide and beginner lessons |

## Metrics Tracked

| Metric | Pilot value | Notes |
|---|---:|---|
| Task completion rate | 9/10 completed core flow | One user needed typed-command fallback in a noisy room |
| Time to fix first error | 2 to 5 minutes | Measured informally during guided sessions |
| Commands recognized correctly | 80% to 95% | Varied by room noise, microphone, and Hindi/English mix |
| Sighted-assistance interventions | 0 to 2 per session | Mostly setup and browser permission prompts |
| Confidence rating before | 3/10 to 6/10 | Self-reported |
| Confidence rating after | 7.5/10 to 10/10 | Self-reported |

## Evidence Boundary

These are anonymized pilot notes, not a controlled research study. Future sessions should record exact timestamps, browser version, assistive technology, and whether each task was independent or teacher-assisted.
